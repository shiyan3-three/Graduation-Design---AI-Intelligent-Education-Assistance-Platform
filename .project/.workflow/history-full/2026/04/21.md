## 任务：B5-2 后端推荐反馈接口

### 做了什么
- 对照 roadmap 第 7 阶段、系统模块设计 B5、API 设计与数据库设计，确认 B5-2 任务合理。
- 在 `backend/routers/recommend.py` 新增 `POST /api/recommend/feedback`。
- 新增 `FeedbackRequest`，限制 `status` 只能为 `completed` 或 `skipped`。
- 反馈接口按 `id + user_id` 查询推荐记录，防止越权操作他人推荐题目。
- 对 pending 题目可更新为 `completed` 或 `skipped`，并写入 UTC `feedback_at`。
- 对已为 `completed` 的题目重复提交返回 409。

### 改动文件
- `backend/routers/recommend.py` - 新增反馈接口、404 领域错误响应、反馈状态更新与更新后记录查询。
- `backend/models.py` - 新增 `FeedbackRequest` 请求模型。
- `backend/tests/test_recommend_api.py` - 新增反馈接口测试，覆盖 completed、skipped、409、404、401、400。

### 关键决策
- 使用 `Literal['completed', 'skipped']` 做请求模型校验，让非法 status 进入项目既有 400 统一错误响应。
- 404 使用接口内领域错误码 `RECOMMENDATION_NOT_FOUND`，同时对不存在和越权保持一致响应，不暴露数据存在性。
- 仅对当前状态已为 `completed` 的记录返回 409；`skipped` 允许后续改为 `completed`，符合本轮 context 约束。

### 遇到的问题
- TDD 红灯阶段 POST 端点尚不存在，反馈测试按预期返回 404。
- 首次实现后 404 走全局 `HTTP_ERROR`，为便于 Review 精确判断，改为接口内返回 `RECOMMENDATION_NOT_FOUND`。
- 完整 discovery 耗时约 147 秒，主要来自既有 LLM/tagging 链路真实请求日志；未发现残留 Python 进程。
