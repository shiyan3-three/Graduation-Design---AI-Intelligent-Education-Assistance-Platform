# 项目路线图

> 维护责任：`Leader Agent`
> 
> 说明：本文件描述项目阶段路线与阶段间顺序。只有当整体推进策略发生变化时，才由 `Leader Agent` 更新。

## 说明

本路线图以《系统模块设计方案》为上位依据，阶段顺序与方案保持一致。

但在正式模块开发前，增加一个“基础设计阶段”，先完成数据库和接口设计。

整体推进顺序调整为：

1. 基础设计阶段
2. 第 1 阶段：智能对话后端主链路
3. 第 2 阶段：智能对话前端接入与联调
4. 第 3 阶段：工具能力实现与验证
5. 第 4 阶段：MCP Server 正式接入
6. 第 5 阶段：`B1 + F1`
7. 第 6 阶段：`B4 + F3`
8. 第 7 阶段：`B5 + F4`
9. 第 8 阶段：`B2/F2` 的流式增强

模块对应关系如下：

- 基础设计阶段：数据库设计 + API 设计
- 第 1 阶段：`B2` 后端基础能力
- 第 2 阶段：`F2` 前端对话页与联调
- 第 3 阶段：`B3` 工具逻辑实现与验证
- 第 4 阶段：`B3` 的 MCP Server 正式化落地
- 第 5 阶段：用户体系
- 第 6 阶段：学习记录与分析
- 第 7 阶段：题目推荐
- 第 8 阶段：流式与体验增强

为了让项目推进更顺，每个阶段内部再拆成更小的可执行任务。

## 基础设计阶段：数据库设计 + API 设计

阶段目标：

- 先确定数据库表结构
- 再确定核心接口契约
- 为后续后端和前端实现提供稳定基础

阶段完成标志：

- 已产出数据库设计草案
- 已产出核心 API 设计草案
- 后续后端任务可以直接按设计进入实现

建议先做的最小任务：

1. 数据库设计初稿
2. API 设计初稿
3. 数据库与接口的对应关系检查

## 第 1 阶段：智能对话后端主链路（B2）

阶段目标：

- 先实现智能对话相关后端
- 固定聊天、会话、消息的基础后端能力
- 先完成非流式版本的后端主链路

阶段完成标志：

- 后端服务可以启动
- `/api/chat` 可正常返回
- 会话与消息的基础接口可工作
- 无直接阻塞性后端异常

建议先做的最小任务：

1. 后端最简 `/api/chat` 接口
2. 后端 `/api/sessions` 与会话消息基础接口
3. 数据写入与读取的最小链路
4. 错误返回格式统一

## 第 2 阶段：智能对话前端接入与联调（F2）

阶段目标：

- 接入最简对话页
- 完成前后端 chat 联调
- 让对话主链路形成可演示闭环

阶段完成标志：

- 前端可以启动
- 页面能发送消息并展示回复
- 前后端字段保持一致
- 无直接阻塞性联调错误

建议先做的最小任务：

1. 前端最简对话页发送与展示
2. 对话历史侧栏的最小占位或基础列表
3. 前后端 chat 联调与字段对齐
4. 前端错误态和加载态最小处理

## 第 3 阶段：工具能力实现与验证（B3 预备阶段）

阶段目标：

- 先把工具能力本身实现清楚
- 在不引入额外协议复杂度的前提下验证工具逻辑
- 为后续 MCP Server 正式接入做准备

阶段完成标志：

- 至少两个工具逻辑可稳定工作
- 工具输入输出已经明确
- 工具失败时有基础错误处理

建议先做的最小任务：

1. 后端先用直接函数调用或轻量封装跑通工具主链路
2. 后端优先接入 `calculator_tool`
3. 后端再接入 `knowledge_tool`
4. 前端补最小工具调用状态展示
5. 明确 `question_tool` 的输入输出与降级策略边界

说明：

- `question_tool` 的三级降级是复杂项，不建议作为本阶段起手任务

## 第 4 阶段：MCP Server 正式接入（B3 正式阶段）

阶段目标：

- 将工具以 MCP Server 方式正式暴露
- 让后端通过 MCP 协议调用工具
- 形成“Agent 决策 + MCP 工具执行”的完整链路

阶段完成标志：

- 存在可独立运行的 MCP Server
- `knowledge_tool`、`calculator_tool` 等工具通过 MCP 暴露
- 后端不再直接调用本地工具函数，而是通过 MCP 调用
- 论文答辩时可以清晰说明 MCP 在系统中的位置与作用

建议先做的最小任务：

1. 建立最小 MCP Server 骨架
2. 将 `calculator_tool` 包装为 MCP 工具
3. 将 `knowledge_tool` 包装为 MCP 工具
4. 后端通过 MCP 客户端完成工具调用
5. 再考虑 `question_tool` 的 MCP 封装

## 第 5 阶段：用户体系（B1 + F1）

阶段目标：

- 增加注册和登录
- 建立“用户拥有自己的会话和数据”这一概念
- 为后续学习记录和推荐做用户隔离

阶段完成标志：

- 用户可以注册
- 用户可以登录
- 用户与会话数据能够关联

建议先做的最小任务：

1. 后端注册接口
2. 后端登录接口与最小鉴权链路
3. 后端将会话归属到用户
4. 前端注册页
5. 前端登录页
6. 前后端登录注册联调

## 第 6 阶段：学习记录与分析（B4 + F3）

阶段目标：

- 让历史问答可查看
- 为消息打知识点标签
- 形成基础薄弱点统计与展示

阶段完成标志：

- 可以按时间查看历史问答
- 可以展示基础标签统计
- 可以得到薄弱点 Top3

建议先做的最小任务：

1. 后端历史会话列表接口
2. 后端单个会话消息详情接口
3. 后端标签打标流程
4. 前端学习记录页和统计展示
5. 前后端学习记录联调

## 第 7 阶段：题目推荐（B5 + F4）

阶段目标：

- 根据薄弱点生成或获取推荐题目
- 展示推荐题目及解析
- 记录学生对题目的处理反馈

阶段完成标志：

- 可返回基础推荐题目列表
- 可展示题目解析
- 可记录“完成/跳过”等反馈

建议先做的最小任务：

1. 后端 `recommend` 接口
2. 后端推荐反馈接口
3. 前端推荐题目页
4. 前后端推荐功能联调
5. 再逐步增强 `question_tool`

## 第 8 阶段：流式输出与体验增强（可选）

阶段目标：

- 把对话从非流式升级为流式
- 优化对话体验和演示效果
- 不破坏已有主链路

阶段完成标志：

- 流式输出可稳定工作
- 工具调用与流式展示不会互相干扰
- 现有功能无明显回归

说明：

- 这是增强项，不是项目能否落地的前提
- 在前 5 阶段稳定前，不建议提前开始

## 第 9 阶段：管理员模块（B-Admin + F-Admin）

阶段目标：

- 增加管理员角色，与普通学生用户隔离
- 管理员可查看全平台用户列表与系统统计
- 管理员可删除用户（级联清理其数据）
- 提供独立的管理后台前端页面

阶段完成标志：

- 数据库 `users` 表增加 `role` 字段，支持 `'student'` / `'admin'`
- 管理员可通过独立入口登录并获得 admin JWT
- `/api/admin/users` 可返回全部用户列表（含统计信息）
- `/api/admin/stats` 可返回系统全局统计
- 前端 `/admin` 路由可访问，展示用户列表与统计看板
- 普通用户无法访问管理员接口（返回 403）

建议最小任务拆分：

1. B-Admin：后端管理员接口（DB 迁移 + 鉴权中间件 + 用户列表 + 系统统计 + 删除用户）
2. F-Admin：前端管理员面板（登录入口 + 用户列表表格 + 统计看板）

## 执行建议

为了让项目顺利进行，建议遵循以下规则：

1. 先完成基础设计阶段，再进入模块开发
2. 智能对话主链路按“后端先、前端后、联调最后”推进
3. 工具能力先验证逻辑，再正式收敛到 MCP Server
4. 每次只在 `current/task.md` 中放一个任务
5. 第一优先级永远是“当前阶段主链路跑通”
6. 不要提前跨阶段做增强项
7. 只有当前阶段基础能力稳定后，再进入下一阶段
