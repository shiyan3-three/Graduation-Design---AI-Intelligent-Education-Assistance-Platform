# 前端 UI/UX 设计方案：AI 智能教育辅导工作台

## 1. 设计总方向

**视觉方向：沉浸式、专注化、结构清晰的“现代 AI 学习工作台”。** 放弃传统的“客服对话框”设计，采用类似现代代码编辑器或专业生产力工具（如 Notion AI / Cursor 界面）的“分栏式工作台”风格。整体视觉语言强调“沉浸感”与“秩序感”，通过大面积的呼吸留白、微妙的深度层级（阴影与毛玻璃效果）以及高信噪比的色彩排布，让学生的注意力完全聚焦于“知识本身”与“辅导过程”。这种设计在毕设答辩展示时，能够有效传达出系统的专业性、复杂度和完成度。

## 2. 页面布局方案

**整体采用「侧边导航 + 沉浸式主工作区」的经典的横向分栏结构。**

- **侧栏（Sidebar）：** 固定在屏幕左侧（占比约 20% - 25%，最大宽度不超过 300px）。包含顶部品牌/平台标识、高亮的新建会话动作，以及按时间倒序排列的历史会话列表。
- **主聊天区（Main Workspace）：** 占据屏幕右侧主体。是一个自上而下滚动的无限流视图。
- **输入区（Input Bar）：** 悬浮吸底固定在主聊天区底部，采用“悬浮岛”式设计，与聊天区内容产生层级脱离，暗示其全局控制权。
- **工具标签区（Tool Area）：** 作为 AI 消息气泡的附属元素，内嵌在 AI 回复的上下文中，不破坏主聊天流。

**端设备差异：**

- **桌面端：** 侧栏常驻，主区域自适应伸缩。
- **移动端：** 侧栏隐藏为汉堡菜单驱动的抽屉（Drawer），输入框紧贴键盘上方，消息气泡横向充满屏幕边缘并缩小内边距。

## 3. 视觉规范

*本规范提供通用设计标记（Design Tokens），工程实现时请映射至具体框架。*

- **主色（Primary）：** 建议采用 **知性蓝（Intelligent Blue, 类似 #2563EB）** 或 **护眼青（Focus Teal, 类似 #0D9488）**。用于核心按钮、光标聚焦状态、当前激活的会话指示器。
- **背景色（Background）：**
  - 全局底层背景：极浅的冷灰色（#F8FAFC），用于衬托工作台面板。
  - 主聊天面板背景：纯白（#FFFFFF），配合微弱的外部阴影，形成“纸张”般的阅读区。
  - 侧栏背景：比全局背景略深的灰白（#F1F5F9）或带有轻微亚克力模糊的半透明色，形成层级区分。
- **文本色（Text）：**
  - 主标题与正文：深石板灰（#0F172A 或 #1E293B），避免绝对的纯黑（#000000）以降低视觉疲劳。
  - 次要信息/时间戳：中灰色（#64748B）。
- **边框色（Border）：** 极浅的分割线（#E2E8F0），仅用于极其必要的模块分割。
- **状态色（Status）：**
  - 成功（Success）：克制的薄荷绿（#10B981）。
  - 失败（Error）：柔和的珊瑚红（#EF4444）。
  - 警告/建议（Warning/Suggestion）：温暖的琥珀色（#F59E0B）。
- **字体排印（Typography）：** 采用系统默认的无衬线字体栈（System Sans-serif）。聊天气泡内的行高（Line-height）建议设为 1.6 - 1.7，以适应大段的教育解析文本。代码块或计算公式需使用等宽字体（Monospace）。
- **几何特征（Geometry）：** 消息气泡使用较大的圆角（如 16px），输入框与面板使用中等圆角（12px），展现教育产品的亲和力。

## 4. 组件级设计

- **Sidebar（侧栏）：** 视觉上应该比主操作区“暗”一个层级。顶部固定系统 Logo，底部预留系统设置或用户信息入口。中间区域支持自定义滚动条。
- **SessionItem（会话项）：** 单行文本，溢出显示省略号（Truncate）。常规状态为透明背景 + 中灰文字；Hover 状态出现极浅的主色背景；Active 状态加深主色背景，文本加粗变为主色，并在左侧增加一根 3px 宽的竖向主色指示条。
- **NewSessionButton（新建按钮）：** 视觉焦点。建议采用轮廓型（Outline）或幽灵型（Ghost）按钮，带有一个显著的 `+` 图标，Hover 时展现轻微上浮动画，避免使用过于沉重的实心色块抢夺聊天区注意力。
- **ChatPanel（聊天面板）：** 纯白背景，居中对齐，最大内容宽度限制在 800px（更宽的屏幕上左右留白），确保长文本阅读时的视线最佳移动距离。
- **MessageBubble (user)（用户气泡）：** 位于右侧。背景填充主色（Primary），文字为纯白。右上角圆角设为较小值（如 4px），其余三角为 16px，形成明确的指向性。
- **MessageBubble (assistant)（AI 气泡）：** 位于左侧。背景为极浅的灰色（#F8FAFC），文字为深色。左上角圆角设为 4px。气泡内支持 Markdown 富文本渲染（粗体、列表、代码块背景需有层次）。
- **ToolBadge（工具调用标签）：** 内嵌在 AI 气泡的最上方或最下方。采用极其紧凑的“胶囊（Capsule）”样式。包含：微型图标 + 工具中文化名称（如“正在查阅知识库…”）。
- **ToolSuggestionAction（“使用工具”按钮）：** 当 AI 提示建议使用工具时，不要用普通文字回复。应渲染成一个独立的、带有轻微投影的“行动卡片（Action Chip）”，包含一个主色调的图标（如计算器、问号）和“点击使用 [某工具]”的文案，视觉上类似一个可点击的快捷指令。
- **InputBar（输入栏）：** 悬浮在主内容区底部，带有向上渐变的透明遮罩（防止遮挡底部文字）。输入框本身带有细微的一圈阴影，支持多行自动伸缩（最大伸缩高度为屏幕高度的 30%）。回车发送，发送按钮嵌在输入框右下角。
- **LoadingState（加载状态）：** 放弃传统的全屏转圈。采用在 AI 气泡位置出现 3 个平滑跳动的圆点（Bouncing dots），或者显示一段带有闪烁光效的骨架屏文案：“AI 正在思考并检索知识...”。
- **ErrorNotice（错误提示）：** 针对网络错误或系统错误，在聊天流中插入一条居中对齐的、带红色危险图标的红色文字提示卡片，并提供“重试（Retry）”的幽灵按钮。

## 5. 工具标签与建议按钮设计

这是系统的核心亮点，需要做到“过程透明，但绝不喧宾夺主”。

- **解析后端数据：** 前端需拦截 `tools_used: [{ tool_name, arguments, result, status }]` 对象。决不能将 `arguments` 或 `result` 的原生 JSON 直接甩在界面上。
- **UI 呈现策略：**
  - 将 `tool_name` 映射为友好的中文（如 `calculator_tool` -> “调用数学计算引擎”）。
  - **成功状态（status="success"）：** 气泡上方出现一个小巧的浅灰色胶囊标签，带有一个绿色的“✔”图标。用户默认不可见复杂结果，但支持“点击展开”查看具体传入的参数和返回结果（适合答辩时展示硬核机制）。
  - **失败状态（status="error"）：** 胶囊标签变为浅红色，带有一个红色的“⚠”图标，文字提示“工具调用受阻，已启用降级策略”。
- **“使用工具”建议按钮：** 如果后端意图判断用户可能需要工具但未触发，将该建议渲染在 AI 文本气泡的正下方。它应该是一个宽度填满气泡 100%、带有虚线或浅色实线边框的交互式按钮区，Hover 时边框变为主色，点击后直接将对应工具指令填入底部的 InputBar 并自动发送。

## 6. 关键交互状态

- **初始空会话：** 聊天区中央显示平台 Logo、一句友好的问候语（“今天想复习什么内容？”），以及 3 个网格排列的“推荐示例问题”卡片。
- **正在发送：** 用户点击发送后，消息立刻“乐观更新（Optimistic Update）”上屏，但右下角显示轻微的灰色“发送中”小箭头。
- **AI 正在处理：** 聊天流底部立即出现 AI 侧的跳动圆点加载状态。如果在调用 MCP 工具，圆点旁需动态闪烁“正在调用计算引擎...”。
- **工具调用失败：** 工具错误不应导致整个消息崩溃。显示红色 ToolBadge，同时 AI 气泡内应有一段兜底的文本回复（体现 Fallback 机制的鲁棒性）。
- **会话切换：** 点击侧栏其他会话时，主聊天区出现极短的 0.2s 骨架屏（Skeleton）渐隐过渡，避免内容瞬间闪烁带来的粗糙感。
- **新建会话：** 当前输入框和聊天列表清空，并以优雅的平滑动画过渡回“初始空会话”状态。
- **网络错误：** 不使用全局弹窗（Toast）打断用户。在最新一条消息下方渲染一条红色的错误栏：“网络连接似乎中断，[点击重试]”。

## 7. 响应式建议

- **桌面端 (>1024px)：** 标准的 25% 侧栏 + 75% 聊天区。输入框定宽居中。
- **平板端 (768px - 1024px)：** 侧栏收缩为只显示 Icon 的“窄边栏”，悬浮态（Hover）时才展开文字。
- **手机端 (<768px)：**
  - 侧栏完全隐藏，通过顶部 Header 的汉堡图标唤出遮罩式抽屉（Drawer）。
  - 主聊天区无左右留白，消息气泡占据 90% 宽度。
  - 输入框取消复杂阴影，紧贴屏幕底边，唤起键盘时随键盘上推。

## 8. 给工程实现者的落地建议

- **组件拆分建议：** 切忌把所有逻辑塞进一个 `ChatPage.tsx`。强烈建议拆分为：`<AppLayout>`, `<Sidebar>`, `<ConversationArea>`, `<MessageList>`, `<MessageBubble>` (内部区分 UserBubble 和 AIBubble), `<ToolBadge>` (解析复杂 tool_used 对象), `<InputArea>`。
- **样式组织方式：** 推荐使用原子化 CSS（如果你选用了支持原子化的方案）或 CSS Modules。避免全局 CSS 污染，尤其是 Markdown 渲染区域的样式，需使用作用域包裹（如 `.markdown-body`）。
- **容易做丑的重灾区：**
  - **滚动条：** 请务必重置浏览器默认的粗陋滚动条，改为细长的、半透明悬浮滚动条，否则会毁掉工作台的精致感。
  - **Markdown 渲染：** AI 返回的表格、代码块如果缺乏样式，会极其难看。必须为 `ul`, `ol`, `table`, `pre` 等元素写一套规范的排版样式。
- **易冲突的状态流（防坑指南）：**
  - **自动滚动：** 每次有新消息或工具状态更新时，自动滚动到底部的逻辑极易出现计算高度错误。建议监听消息数组的 `length` 和工具状态，使用 `scrollIntoView({ behavior: 'smooth' })`。
  - **状态解耦：** `tools_used` 是一个复杂对象数组，切勿试图将其用 `JSON.stringify` 直接渲染。请专门编写一个 `parseToolsStatus` 辅助函数来提取状态。
