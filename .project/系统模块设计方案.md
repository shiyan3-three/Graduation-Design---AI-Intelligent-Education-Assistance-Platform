# 系统模块设计方案

**课题：MCP 应用和智能体在教育场景中的应用**  
**系统名称：AI 智能教育辅导平台**

---

## 一、系统整体架构

```
┌─────────────────────────────────────────────┐
│              前台（学生端）                    │
│         Vue 3 + Element Plus                │
│   登录/注册 | 智能辅导 | 学习记录 | 推荐题目   │
└──────────────────┬──────────────────────────┘
                   │ HTTP / REST API
┌──────────────────┴──────────────────────────┐
│              后台（服务端）                   │
│            Python FastAPI                   │
│   用户接口 | 对话接口 | 记录接口 | 推荐接口   │
└──────────────────┬──────────────────────────┘
                   │ 调用
        ┌──────────┴──────────┐
        │    LLM 智能体 Agent  │
        │ 大模型 API 原生      │
        │ Function Calling    │
        └──────────┬──────────┘
                   │ MCP 协议（官方 Python SDK）
                   ▼
        ┌─────────────────────┐
        │   统一 MCP Server    │
        │  （单进程，3个工具）  │
        │ ┌─────────────────┐ │
        │ │ knowledge_tool  │ │  → 百度搜索 API 权威知识
        │ │ question_tool   │ │  → 三级 Fallback 出题策略
        │ │ calculator_tool │ │  → sympy 符号计算
        │ └─────────────────┘ │
        └──────────┬──────────┘
                   │
        ┌──────────┴──────────┐
        │     SQLite 数据库    │
        └─────────────────────┘
```

## 二、前台模块（Vue 3 + Element Plus）

> **选型理由**：Element Plus 官方文档全中文、组件成熟、Vue 模板语法直观，AI 生成代码质量稳定，适合长时间未接触前端的开发者重新上手。

> **前端状态管理方案**：采用 Vue 3 官方推荐的 **Pinia** 管理全局状态（JWT Token、用户信息、当前会话 ID），配合 `localStorage` 做 Token 持久化，确保刷新页面后登录态不丢失。

### 模块 F1：用户认证页面
| 功能 | 说明 |
|------|------|
| 注册页 | 填写用户名、密码、年级、主修学科 |
| 登录页 | 账号密码登录，获取 Token（有效期 7 天，演示期间无需刷新） |

### 模块 F2：智能辅导对话页（核心页面）
| 功能 | 说明 |
|------|------|
| 消息气泡界面 | 展示学生问题与 AI 回答 |
| 工具调用状态 | AI 调用 MCP 工具时显示"正在思考..." |
| 对话历史侧栏 | 历史会话列表，可切换 |

> **实现策略**：先做非流式版（完整回答后一次性显示），功能全部验证通过后再加打字机效果，避免流式输出与工具调用同时处理的复杂度。

### 模块 F3：学习记录页
| 功能 | 说明 |
|------|------|
| 对话历史时间线 | 按日期展示历史问答记录 |
| 知识点标签统计 | 柱状图展示各知识点提问频率 |
| 薄弱点报告卡片 | 展示"近期提问最多的3个知识点" |

### 模块 F4：题目推荐页
| 功能 | 说明 |
|------|------|
| 推荐题目列表 | 基于薄弱点展示 1-3 道练习题 |
| 题目展开/收起 | 点击展开显示 AI 解析 |
| 完成/跳过反馈 | 记录学生对推荐题目的处理状态 |

## 三、后台模块（Python FastAPI 服务端）

### 模块 B1：用户管理模块
| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/register` | POST | 注册新用户，存入数据库 |
| `/api/login` | POST | 验证账密，返回 JWT Token |
| `/api/user/profile` | GET | 返回当前用户的画像信息 |

**数据库表：** `users(id, username, password_hash, grade, subject, created_at)`

---

### 模块 B2：智能对话模块（核心模块）
| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/chat` | POST | 接收提问，调用 Agent，返回回答 |
| `/api/sessions` | GET | 获取当前用户的历史会话列表 |
| `/api/sessions/{id}` | GET | 获取某次会话的完整消息记录 |

**核心逻辑（Agent 循环）：**
1. 接收学生提问
2. 构建 Prompt（引导式辅导，不直接给答案）
3. 调用大模型 API，将 MCP 工具描述作为 `tools` 参数传入
4. 模型通过**原生 Function Calling** 决定是否调用工具、调哪个
5. 执行统一 MCP Server 中对应的工具函数
6. 将工具结果塞回对话，继续调用模型生成最终回答
7. 返回完整回答，异步写入数据库

> **为什么不用 LangChain**：封装层深，出错难定位，MCP 支持包尚不成熟，版本迭代频繁。直接调用 API 原生 Function Calling，代码逻辑全部透明，答辩时可完整解释每一步。

**数据库表：** `sessions(id, user_id, title, created_at)` | `messages(id, session_id, role, content, tools_used, created_at)`

---

### 模块 B3：MCP 工具集成模块（论文亮点）

> **架构决策**：将三个工具合并在**同一个 MCP Server 进程**中注册，避免多进程部署管理。MCP 协议的亮点在于标准化的工具封装与调用方式，与进程数量无关。

| Tool 名称 | 功能 | 实现方式 |
|----------|------|---------|
| `knowledge_tool` | 查询某知识点的权威解释 | 接入**百度搜索 API**（千帆 `web_search`），实时检索全网权威知识内容 |
| `question_tool` | 针对知识点获取练习题（三级降级策略） | 见下方详细说明 |
| `calculator_tool` | 安全执行数学表达式 | 使用 **sympy** 符号计算库（非 eval） |

> **knowledge_tool 架构意义**：避免 Agent 内部再调用另一个 LLM 的逻辑冗余（套娃），转而接入外部客观权威数据源（百度搜索 API），向评审完整展示 MCP 协议连接外部世界的核心初衷。百度搜索 API 国内稳定可用（每月 1500 次免费），中文教育内容覆盖好，答辩演示可控。

#### `question_tool` 三级降级获取策略（Fallback Mechanism）

体现 Agent 通过 MCP 协议调用多源异构数据的核心能力，保障在任意环境下均能返回有效题目。

**第一级：本地结构化题库（首选，稳定优先）**
- **数据源**：开源 [C-Eval](https://github.com/hkust-nlp/ceval) 数据集，预处理为本地 SQLite 数据库
- **实现**：Agent 通过 SQL 查询，按知识点精确匹配并抽取真实学科考题
- **架构意义**：演示 Agent 接入本地离线关系型数据库的能力；100% 稳定、零延迟，保障核心演示环节不受网络影响

**第二级：实时联网检索（次选，本地未命中时触发）**
- **数据源**：DuckDuckGo Search API 等免费搜索接口
- **实现**：本地题库未命中对应知识点时，触发次级路由，实时抓取教育网站和题库论坛的公开例题与解析
- **架构意义**：演示 Agent 突破静态知识库边界，利用 Web 工具动态获取互联网实时信息的高级能力

**第三级：LLM 动态生成（兜底，搜索失败时触发）**
- **数据源**：大模型自身生成能力
- **实现**：当搜索接口断网、超时或未抓取到有效数据时，通过严格的 Few-Shot Prompt（少样本提示词）约束模型输出标准 JSON 格式题目
- **架构意义**：展现系统容错能力（Fault Tolerance）与鲁棒性，确保极端情况下依然返回有效数据，前端不崩溃

> **为什么不用 eval**：eval 执行用户传入字符串存在安全风险，sympy 是学术级符号计算库，支持代数、三角、微积分，安全性和功能性均优于 eval。

**MCP Server 暴露的 Tool 接口：**
```
knowledge_tool(topic: str) → str        # 返回知识点解释文本
question_tool(topic: str) → dict        # 按三级策略返回题目+选项+答案+解析
calculator_tool(expression: str) → str  # 返回 sympy 计算结果
```

### 模块 B4：学习分析模块
| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/analytics/tags` | GET | 统计用户历史消息中各知识点标签的频率 |
| `/api/analytics/report` | GET | 返回薄弱点 Top3 列表 |

**核心逻辑：** 每次对话结束后，调用 LLM 对消息内容打知识点标签。

> **稳定性保障**：为 LLM 提供固定的预设标签列表（如 20 个知识点），让模型只从列表中选择返回值，避免自由发挥导致标签不一致或格式混乱。

**数据库表：** `message_tags(id, message_id, tag, created_at)`

---

### 模块 B5：题目推荐模块
| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/recommend` | GET | 根据薄弱点调用 question_tool，返回推荐题目 |
| `/api/recommend/feedback` | POST | 记录学生"完成/跳过"的反馈 |

**核心逻辑：** 读取 B4 薄弱点 Top3 → 调用 `question_tool` MCP 工具动态出题 → 返回题目列表

## 四、技术栈总览（可降级）

| 层级 | 主力方案 | 兜底方案 |
|------|---------|---------|
| 前端 | **Vue 3 + Element Plus** | Streamlit（全 Python） |
| 后端 | Python FastAPI | Python Flask |
| Agent | 大模型 API **原生 Function Calling** | 直接调 API，不用 tools |
| MCP 集成 | 分两阶段落地（见下方说明） | 普通函数直接调用 |
| 数学计算 | **sympy** | 同左 |
| 数据库 | SQLite | JSON 文件存储 |

> **切换原则**：前端可随时替换，后端逻辑与 MCP 模块**完全不变**。

> **MCP 集成两阶段落地策略**：**前期开发阶段**，先使用大模型原生 Function Calling（普通 Python 函数）跑通全部业务逻辑，确保 MVP 版本快速落地；**系统稳定后**，再通过官方 `mcp` Python SDK 将工具函数标准封装为统一 MCP Server。此策略规避了 MCP 协议较新导致的 AI 代码幻觉风险，同时保证最终产出符合论文的技术要求。

## 五、建议开发顺序

| 阶段 | 目标 | 包含模块 |
|------|------|---------|
| **第1阶段** | 能对话（非流式） | B2 接口 + F2 对话页 |
| **第2阶段** | MCP 工具生效 | B3 统一 MCP Server |
| **第3阶段** | 有用户概念 | B1 + F1 登录注册 |
| **第4阶段** | 记录可查 | B4 + F3 学习记录 |
| **第5阶段** | 推荐功能 | B5 + F4 推荐页 |
| **第6阶段**（可选） | 流式输出效果 | B2 升级 + F2 升级 |

> 做到第3阶段，系统即可演示，可以开始写论文。第6阶段为锦上添花，不影响论文质量。
