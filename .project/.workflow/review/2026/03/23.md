以下是实现阶段需要注意的关键点，建议 Leader Agent 在后续协作中提醒 Coding Agent：

1. **SQLite 配置风险**

   - `messages.sequence_no` 需由应用层递增维护，不能仅依赖 `created_at` 时间戳
   - 高并发或秒级时间戳相同时容易导致消息乱序

### 阻塞问题

- [ ] **`backend/models.py:9` — Python 3.9 不支持 `int | None` 语法，导致服务无法启动**。Pydantic v2 在运行时求值类型注解时抛出 `TypeError: unsupported operand type(s) for |: 'type' and 'NoneType'`。`from __future__ import annotations` 只推迟了注解求值，但 Pydantic 仍会在运行时 eval。**修复方案**：将所有 `X | None` 改为 `Optional[X]`，将 `list[dict[str, Any]]` 改为 `List[Dict[str, Any]]`（从 `typing` 导入），或安装 `eval_type_backport` 包。涉及文件：`models.py`、`chat.py`、`services/llm.py`。
- [ ] **人类运行已确认 acceptance 第 1 条不通过** — `uvicorn` 启动时因上述 TypeError 立即崩溃，无任何输出。

### 非阻塞问题

- [ ] `backend/services/llm.py:24` — LLM 真实调用失败时 `except Exception` 静默 fallback 到 mock，无任何日志输出。建议至少加一行 `logging.warning`，否则 API key 错误、网络超时等问题在联调时完全无迹可循。
- [ ] `backend/routers/chat.py:39-96` — `post_chat` 分为两次独立 `get_connection()` 块：第一次写入用户消息并 commit（第 68 行），第二次写入助手消息并 commit（第 96 行）。建议合并为一次连接上下文，在 LLM 返回后统一 commit，避免出现"只有用户消息但无助手消息"的中间状态。
- [ ] 缺少 `.env.example` 或环境变量说明 — `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`、`LLM_MOCK_MODE`、`APP_DB_PATH` 等关键配置缺少模板文件。建议添加 `.env.example`。
- [ ] `backend/routers/chat.py:230` — `_sqlite_timestamp_to_iso8601` 硬拼 `"Z"` 后缀。SQLite `CURRENT_TIMESTAMP` 返回 UTC 时间语义上正确，但如果服务器时区不是 UTC 会产生错误标记。当前阶段可接受。
